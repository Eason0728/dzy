# 需求：損益試算原生化（requirements.md）
版本：v1.1 / 2026-11-03（Eason 已確認：Q1–Q6 全照建議）
進度檔：`docs/pnl-native/progress.md`

## 1. 要解決的問題
- 管理系統「財務部門 → 損益試算」現在是用內嵌框載入另一個網站（mala-pnl.github.io）。等後端回應的那幾秒到一分鐘，畫面會露出那個網站自己的帳號／通行碼登入框，看起來像登入失效（2026-11-03 Eason 回報）。
- 根本原因是兩套系統疊在一起：損益網站有自己的登入、外觀、帳號，管理系統又包一層。
- 後端跑在 Google Apps Script，冷啟動慢（10 秒以上很常見），代轉逾時要等 60 秒。

## 2. 目標（Eason 2026-11-03 決定）
1. **畫面內建在管理系統**：損益試算四頁（儀表板、填資料、匯入、設定）用管理系統自己的程式重做，不再嵌外部網站，永遠不會出現第二個登入框。
2. **後端一起搬到 Mac mini**：資料與計算從 Google 試算表＋Apps Script 搬到 Mac mini（比照現金帳、調撥、稽核），速度變快、不怕冷啟動。
3. **外觀跟管理系統一致**：字型、按鈕、卡片照管理系統；損益原本的三品牌主題色不帶過來。
4. **四頁一次做完才切換**：中間不做新舊並存；切換前照現況使用（嵌入時登入框外露的問題不另外小修）。

## 3. 使用者與權限（沿用管理系統，不新增）
| 誰 | 管理系統權限 | 能做什麼 |
|---|---|---|
| Eason | pnl.admin | 全部，含設定、定稿、解除定稿、維護功能 |
| 會計 | pnl.write | 填資料、匯入、確認為 0、看儀表板 |
| 財務部主管 | pnl.read | 只看儀表板與損益數字 |
- 可看哪些門市：沿用現在的規則（管理系統權限＋損益裡的可看門市設定）。
- 店長不開權限（2026-09-27 定，不變）。
- 損益自己的帳號、通行碼、邀請碼、「記住 7 天」：原生版不需要，全部退場。

## 4. 核心功能（＝現在的功能全部保留，行為不變）
- **儀表板**：本月待補 N 項、六列（營業額、稅後淨利、食材、人事、可控、不可控）12 個月走勢、估算標示（估）、全部門市＋品牌篩選。
- **填資料**：待補總覽＋食材／人事／可控／不可控／營業收入五類完整資料；新增、作廢、附件、確認為 0。
- **匯入**：POS 檔與自訂範本匯入、預覽、已有其他來源提示與連帶作廢。
- **設定**：門市、科目、門市科目（固定費、攤提）、連接器、匯入範本、建立草稿、立即拉取連接器、重新帶入固定值、定稿／解除定稿、異動紀錄、匯出 CSV。
- **原本在試算表選單的維護功能**（初始化、自我檢查、同步科目範本、套用光復連接器對應等）：搬到設定頁，只有 pnl.admin 看得到。
- **自動化全部照舊**：每天 05:15 POS／LINE Pay 推送、貨單推送、費用請款推送（每 15 分鐘）、每天 06:30 每日更新（含人事與成本估算）、每月 1 號 06:00 建上月草稿、失敗走通知匣、排程守門健康檢查。
- **計算結果必須逐元相同**：搬家前後同一個月的損益，八大項每項差 0 元（以 8 月裁判資料＋光復 9、10 月實際資料比對）。

## 5. 不做的事
- 不改任何計算規則、科目、估算邏輯。
- 不新增功能（新功能等搬完再談）。
- 不碰美村／南昌每月 8 號的損益資料表單（mala-pnl-form）。
- 不碰光復手工 Excel 損益表。

## 7. Eason 決定（2026-11-03「全照建議」，以下各題均採第一個選項）

- **Q3 舊入口退場**：切換當天 mala-pnl.github.io、損益帳號、邀請碼一起停用，舊網址改顯示「已搬到管理系統」（建議）｜再並行兩週。
