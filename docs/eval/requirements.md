## 1. 要解決的問題
1. 績效評核目前只服務新竹光復一家店：一份名單、一個主管通行碼、一套題目，墨竹亭、一悟、小辛辣美村／南昌都用不了。
2. 同仁要多記一組帳號密碼（舊系統的密碼是明文存在試算表，主管通行碼共用一組）。
3. 管理系統已經有同仁名單、單位、職稱、權限，評核卻各自維護一份名單，人員異動要改兩邊。

## 2. 使用者
| 身分 | 要做的事 |
|---|---|
| 一般同仁（計時、正職） | 每季填互評＋自評、給夥伴留言（可匿名）、看自己的成績與時薪落點 |
| 店長（含中央工廠廠長） | 也是同仁；另外替新人做入職考核、評本店正職 KPI、給回饋、± 調整 |
| 區經理／品牌總監 | 看自己品牌各店的結果（Q5 決定細節） |
| 人資 | 追誰還沒填、看全集團總覽、定稿本季、列印 PDF |
| Eason | 開權限、改題庫與範本 |

## 3. 核心功能（沿用舊系統全部功能，差別只在「多單位」）
舊系統現有、全部保留：
- 互評（星等 1～5，題目附五級說明）、自評（自己算一票）、三種留言（給下一季的自己、給夥伴可匿名、給公司全匿名）
- 計分：計時＝態度 30＋表現 70；正職＝態度 30（星數×1.2）＋主管評 KPI 70；主管 ± 調整；上限 100 分
- 等第 A／B／C／D 對獎金基數（只給正職看）、時薪級距落點（只給計時看）
- 新人到職滿一個月由店長考核一次（不併入季分數）
- 定稿本季（鎖住當季分數，之後改題目不影響）、漂移提醒、列印 PDF
- 草稿自動儲存、每季只能送一次、按鈕顯示等待秒數、日夜背景

因為多單位要改的：
| 現在 | 搬進來之後 |
|---|---|
| 名單＝試算表「帳號」分頁全部的人 | 名單＝管理系統同仁名單，依所屬單位分店 |
| 互評＝全部帳號互評 | 依 Q3：同一家店互評 |
| 店長＝「正職職稱」分頁寫店長的人，看得到所有新人 | 店長＝管理系統職稱店長，只看得到自己店的新人 |
| 一個主管通行碼看全部 | 依 Q5 用帳號權限，沒有共用通行碼 |
| 題目一套、內容是小辛辣攤車／炸燙／自助吧 | 依 Q1：態度題共用、表現題品牌各一套 |
| PDF 檔名寫死「新竹光復店」 | 依店名自動帶 |
| 紅色小辛辣招牌、新竹日出日落 | 改成管理系統外觀；品牌色只用在 PDF 抬頭 |

## 5. 不做（本期範圍外）
- 不自動把等第／時薪寫進薪酬管理（仍由人資看結果自己核）
- 不做跨店支援同仁的互評（支援的人只在主要單位評）——除非 Eason 另外要
- 不做 LINE 提醒填寫（現在由店長在群組發）

## 6. 驗收（需求層級）
- 三品牌任一家門市的同仁，用管理系統帳號登入就能填自己店的互評＋自評，看不到別家店的人
- 店長只看得到自己店的新人考核與 KPI；Q5 的權限照答案運作
- 光復現有計分規則全部照舊（同一份資料算出的分數跟舊系統一致）
- 加模組只動 `platform/registry.js` 一行

- 上線節奏（Eason 確認後）：先給本機可測版本 → 光復先試一季 → 再開給其他店。
