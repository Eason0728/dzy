## 1. 兩個做法（推薦 B）

### A. 照原需求：轉進「表單簽核」
- 新表單種類「出勤申請（值班主管）」，由 mini 從打卡複製一張進表單簽核、上層在那裡核、結果再由 mini 寫回打卡。
- 要新做：打卡端 5 支服務動作（列出、連結、寫回核決、作廢、名單推送）、管理系統新表單種類＋系統代建單入口＋路由＋畫面、mini 雙向同步排程（含同仁撤銷、寫回失敗重試）、證明照片要另外接（照片在光復雲端硬碟，表單簽核看不到）。
- 兩份資料（打卡申請＋表單）要一直對齊，任何一邊漏同步就是單據卡住。

### B. 推薦：改到「考勤管理 → 申請審核」審（上層本來就在那裡看得到）
- 打卡端擋住「一般主管鑰匙」對值班主管本人申請的核准／退回／作廢，只收營運系統專用那把（營運系統已經用管理系統的表把關誰能核誰）。
- 管理系統那張「誰核誰」表補一條：**對象是值班主管時，跳過同店也持主管鑰匙的人**（例：正職兼值班 → 不給同店店長核，往上給區經理／督導）。
- 好處：不複製資料、照片／打卡比對／退回理由／LINE「我的申請」／核定預填全部沿用；上層就是今天已經在核店長申請的那群人。
- 代價：審核地點不是「表單簽核」而是「考勤管理」（人資部門底下）。

以下 §2 之後兩案共用（認人、擋法、舊單、單一主管店、查不到上層）；B 案專屬的寫在 §6，A 案專屬寫在 §7。

## 2. 「本人」怎麼認

1. **managers 分頁加一欄 `emp_id`（附在最後）**。有填＝以工號為準。
2. 沒填 → 用姓名（去空白）對**該店在職名冊**：剛好一人 → 就是他；**同名兩人以上 → 兩人都當值班主管處理**（寧可多送上層，不讓同名的人互核），並在檢查清單報「同名，請在 managers 填 emp_id」；對不到任何人 → 報「對不到名冊」（這種主管自己的申請也不存在，不影響）。
3. 跨店：mini 每天 00:10 同步時，`svc_roster` 每列多回 `duty_mgr`（打卡端用上面 1、2 算），mini 寫進管理系統 staff_clock，用 DZY 編號合併 → **在任何一家店是值班主管，他在每家店的申請都送上層**（例：店長到別店支援時送的加班單）。mini 再把各店名單推回打卡（指令碼屬性 `REQ_UPPER_EMPS`）。
   - 本店判斷是即時的（打卡端直接讀 managers）；跨店最多晚一天（下次同步）。
4. 只算 `active=TRUE` 的列；「營運系統專用」那列（allow_acting）不是人，不算。

## 3. 擋在哪、畫面怎麼顯示

  - `mgr_req_decide_batch`：略過，理由「值班主管本人的申請，送上層審核」。
