## 1. 背景與範圍

- 貨單辨識系統兩半：門市拍貨單（已在「營運部門 → 門市營運」，**不動**）；會計核對入帳（還在自己的網址，**這次搬**）。

- **計算規則、入帳規則、紅黃字、價格提醒、損益推送一律不改**（正本仍在貨單系統 plan.md）。

## 3. 做法（給工程看，Eason 不必讀）

- 照抄「門市營運」：iframe 嵌貨單網頁（`?embed=dzy`）＋平台發一次性入場券、貨單後端憑服務金鑰向平台兌換成同仁編號、再對到貨單系統內的會計帳號與品牌。理由：照片與二十多支 API 在 iframe 內直接用，薪酬那種逐支代轉對照片太重。
- 瀏覽器不拿任何金鑰；兌換在 Mac mini 上兩個本機服務之間。
- dzy：新增 `modules/purchase/`（模組 id `purchase`）（dept `fin`、keepAlive 30 分、頁頂分頁）、`platform/registry.js` 一行；權限碼 `platform.purchase`（平台命名空間：模組 ns＝platform 才能換平台入場券，同 platform.storeops）不列鎖碼；預設規則「總部財務部門全部職稱」有，Eason 可用個別例外加人（Q1-A）。
- 貨單系統：新增入場券兌換、「同仁編號↔會計帳號」對照與品牌指派（Q2）、嵌入模式（藏自己的側欄、聽管理系統的分頁指令）、過渡期開關（Q3）。
- 部署順序：Mac mini（貨單後端＋平台後端）→ dzy 前端 → 貨單網頁。每一步都先給本機可測版。
