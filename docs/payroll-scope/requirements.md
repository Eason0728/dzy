# 薪酬管理依負責門市分權限 — 需求文件 v0.1（待 Eason 確認）

> 狀態：2026-10-28 Eason 已確認第 1～3 節；第 6 節 Q1 A・Q2 A・Q3 A（「照建議」）。
> 公開 repo：本檔不寫真名、不寫網址主機名、不寫金鑰。

## 0. 一句話

薪酬管理（人資部門 → 薪酬管理，嵌入的薪資頁）改成**只有財務部同仁能進**，
每位財務同仁**只看得到、只操作得到自己負責的門市**。誰負責哪幾家，由 Eason 在「權限設定」勾選。

## 1. 為什麼

- 現在權限 `payroll.write` 只有一個開關，開了就是**全集團每家門市的薪資都能看能改**
  （平台代轉不依門市裁切，薪資頁的門市選單也列出全部門市）。
- 財務部同仁各自負責不同門市，Eason 要的是「各管各的」，薪資是最敏感的資料。

## 2. Eason 已確認的事（2026-10-28）

| # | 決定 |
|---|---|
| D1 | 薪酬管理只有**財務部同仁**能進（人在財務部就自動有，不必再逐一開）。其他人，包括店長、人資，一律看不到。 |
| D2 | 每位財務同仁只看自己**負責的門市**。 |
| D3 | 負責門市由 **Eason 本人在「權限設定」勾選**（不交給財務主管或人資）。 |
| D4 | 負責的門市**能看也能操作**：重新計算、鎖定／解鎖本月、改員工主檔、改該店參數、獎金、假別、出勤紀錄表匯出等。沒負責的門市**完全看不到**。 |
| D5 | **全集團共用的部分只有 Eason（系統管理者）能看能改**：集團總覽、集團預設參數、紅字天數同步、門市設定（新增／改門市）、集團共用的假別表。這裡的「看」指**集團層級的控制畫面**；負責門市的參數頁照常顯示合併後實際生效的參數值（集團預設＋本店覆寫），計薪必須看到（Eason 2026-10-29 裁示，見 spec §10）。 |

## 3. Claude 做的決定（Eason 可推翻）

- C1 系統管理者（role admin）照舊看全部門市，不受負責門市限制。
- C2 財務部同仁**還沒被勾任何門市**時，進薪酬管理只顯示「尚未指派負責門市，請洽系統管理者」，不顯示任何薪資資料。
- C3 可勾的門市清單＝薪資系統門市表裡的門市（含停用的，標「停用」）。新開門市只要薪資系統建好，就會出現在勾選清單裡，不必改程式。
- C4 一人可勾多家；同一家可以有多位財務同仁負責。
- C5 擋的位置在**伺服器端**（平台代轉／Mac mini），不是只把薪資頁的選單藏起來：就算有人改瀏覽器送出的門市代碼，也拿不到沒負責的門市。
- C6 薪資頁的門市選單只列負責的門市；只負責一家時直接進那家。非系統管理者看不到「集團總覽」分頁，參數設定也沒有「存成集團預設」的選項。
- C7 稽核紀錄維持現行做法（操作人由登入身分決定），不另做。
- C8 「財務部同仁」照現行權限系統認定（與貨單、收支、調撥、損益同一套）：在權限設定把「總部・財務部・全部職稱 → 薪酬」打開即可，兼任財務部同樣算（照權限系統既有的兼任處理）。系統帳號（非同仁帳號）只有 role admin 能進。`payroll.write` 維持鎖碼，所以只有系統管理者能開關它。
- C9 D3、D5 的「Eason」＝role admin（目前只有 Eason）。人資主管雖有權限設定頁，但勾負責門市跟鎖碼一樣只有 admin 能改。
- C10 可以改薪資後端（Payroll.gs）來配合擋門市，只要不動計算規則（第 4 節）；擋的方式交給規格決定。

## 4. 不做的事（非目標）

- 不改任何薪資計算規則（payCalcOne 等一行不動）。
- 不動同仁自己查薪資單（打卡頁「我的薪資」／my.html）。
- 不做「只能看不能改」的分級（D4：負責的店就是全部功能）。
- 不做依品牌、依區域自動帶門市；一律 Eason 逐人勾。

## 5. 失敗的樣子（反目標）

- 財務同仁 A 透過任何方式（改網址、改瀏覽器送出的資料、用「集團總覽」、匯出）看到沒負責門市的任何一個人名或金額。
- 財務同仁改到集團預設參數或紅字天數，導致別家門市的薪資跟著變。
- 上線時 Eason 自己被擋在門外，或薪資頁變成沒有選單。
- 門市清單回應帶出各店打卡試算表 ID 給非系統管理者。

## 6. 待決（要 Eason 回答）

| # | 題目 | 選項 | 推薦 |
|---|---|---|---|
| Q1 | 舊的「網址帶管理金鑰」薪資頁（`payroll.html?k=`）怎麼處理 | A 這次上線時一起換掉管理金鑰（舊連結失效，只剩管理系統這條路）／B 舊連結先留著 | **A**：舊連結能看全部門市，不關掉的話分權限等於沒做；而且原本就排定「新路用一週後換金鑰」、舊金鑰 10-20 曾在對話中貼出 |

| Q3 | 員工換店（主檔把某人的門市從 A 改成 B） | A 兩家都負責的財務同仁才能改，否則擋下請 Eason 改／B 只有 Eason 能換店／C 負責原本那家就能改 | **A**（C 會讓人把員工「送」到自己看不到的店，或從別店「拉」人過來看薪資） |

### 6.1 Eason 的答案（2026-10-28）

- Q1 A：上線時一起換管理金鑰，舊 `?k=` 連結失效。
- Q2 A：非財務部同仁的個別例外上線後收回（上線前先列名單給 Eason）。
- Q3 A：換店要兩家都負責，否則擋下由 Eason 改。

## 7. 現況盤點（2026-10-28，給寫規格的人）

- 薪資頁共有 23 支後端動作會經過平台代轉（讀 12、寫 11，白名單在 `apps-script/platform/Auth.gs` 的 `PROXY_READ_ACTIONS.payroll`／`PROXY_WRITE_ACTIONS.payroll`）。
  門市代碼（body.store）目前由瀏覽器送、平台與 Mac mini 原樣轉給薪資後端，沒有任何檢查。
- 多數動作只看單一門市（body.store）。**會跨門市的**：
  - 讀：`payroll_get`（回全部門市的薪資計算結果）、`payroll_group`（集團總覽）、`payroll_store_get`（全部門市表，含打卡試算表 ID）；
    `payroll_month`／`payroll_master_get` 是單店但**附帶完整門市表**；`payroll_leave_type_get` 含集團共用列。
  - 寫：`payroll_store_set`（整張門市表覆寫）、`payroll_holiday_sync`（集團共用紅字天數）、
    `payroll_config_set` 不帶門市＝存成集團預設、`payroll_leave_type_set` 不帶門市＝寫集團共用、
    `payroll_master_set` 每一列可自帶門市（可寫進別家）。
- 薪資頁沒帶門市時，薪資後端預設當成小辛辣光復（SSLGF）。集團預設以「門市欄空白」表示。
- 平台 `proxyAuthorize_` 對 payroll 目前只回 `{secret, filterNode, isWrite, operator}`；
  Mac mini 的 `filterResponse` 只認列陣列鍵，套在薪資回應會把資料整個刪掉，**不能直接沿用稽核的裁切**。
- `payroll.write` 是鎖碼（PERM_LOCKED），目前做法是 Eason 用個別例外逐人開。
- 薪資門市表另有 `dzy_node` 欄（薪資代碼對應管理系統單位），可供日後對照，但本案是 Eason 逐人勾，不依單位自動帶。
- 2026-10-28 另一個對話正在薪資系統新增門市（墨竹亭光復店、小辛辣總部、墨竹亭總部；六張犁已在表上，HQ＝鼎兆元總部）。

## 8. 交給規格（spec）決定的事

- 負責門市存在哪裡、權限設定畫面長怎樣（例：財務同仁那列多一欄門市勾選）。
- 每支跨門市動作的處理方式：直接擋、改成只回負責門市、或剝掉敏感欄位。
- 部署順序（原則：Mac mini／平台後端先、薪資頁後，任何時刻 Eason 都進得去）。
- 測試：每支動作都要有「帶沒負責的門市 → 被擋」的案例，跨門市回應要驗沒有混進別店資料。
