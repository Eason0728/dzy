## 1. 要解決的問題

排班月曆版（Gist，排班自編、靠姓名）、管理系統人員資料（DZY001）、佈告欄（S-xxx，從打卡同步）。
新人要在值班核定建一次、薪資再建一次、佈告欄再按一次同步；對不上就出事——2026-10-12 佈告欄 LINE 自動登入
就因央廚同步來的帳號被刪、手動重加，接不回原本那個人。
薪資的請假與工時目前**用姓名**對人（Payroll.gs），同名會直接算錯錢。

本期目標：**新人只在管理系統建一次檔，打卡、佈告欄自動跟上；離職按一次，全部停。**

## 4. 核心功能
### F1 編號對照
- 每位同仁在管理系統多一塊「打卡編號」：主店一筆＋支援店各一筆（例：DZY014 ↔ 光復 E07、金山 MZTJS12）。
- 第一次建表：把六套打卡名冊的在職同仁，用姓名比對 DZY 名單，分成三堆：
  - 唯一對上 → 列出來給確認人勾「對」（不自動生效）
  - 同名、或一人對到多筆 → 人工指定
  - 打卡上有、DZY 沒有（例：9 月沒領薪的 6 人、央廚其他 11 人若還在打卡）→ 依第 6 題處理
- **不自動猜**：沒有人工確認的對照不生效（2026-10-12 佈告欄案例的教訓）。
- 對照可改，每次改留紀錄（誰、何時、從哪筆改成哪筆）。

### F2 店長新增新人
- 店長在管理系統「同仁名單」按新增，填：姓名、主店（固定為自己單位）、職稱、到職日、手機。
- 送出後：
  1. 管理系統建 DZY 編號（接續最大號），狀態「未開通」
  2. 主店打卡名冊自動多一筆，打卡編號照該店原本規則取號（E 接續最大號）
  3. 畫面顯示新人的打卡連結＋LINE 綁定方式，店長當場交給新人
- 擋：同一店有在職同名者不能建（薪資用姓名對人），要加註區分（例：王小明-B）。
- 打卡那邊寫失敗 → 管理系統的那筆標「打卡未建」，首頁待辦顯示，可按重試；不會出現「有 DZY 沒打卡、沒人知道」。
- 薪資層不在這裡填：薪資系統自己會標「本月新增」，會計照舊補。

### F3 離職
- 店長或總部按「離職」，填最後上班日（依第 2 題）。
- 結果：DZY 狀態停用、帳號登出；主店與所有支援店的打卡名冊 active 改 false（保留紀錄、不刪）；佈告欄同步停用。
- 編號永不回收（DZY 與打卡編號都是）。

### F4 跨店支援
- 在同仁頁加「可支援的店」，加一家 → 那家打卡名冊新增一筆、記進對照；移除 → 那家停用。
- 誰可以加：依第 4 題。

### F5 值班核定的新增同仁退場
- 新做法上線後，值班核定的「新增同仁」按鈕改成提示「請到管理系統新增」。
- 跑順兩週後拿掉（2026-10-13 第 6 題已定）。Mac mini 停機時怎麼辦見第 3 題。

### F6 佈告欄改讀管理系統
- 佈告欄的同仁名單改從管理系統拿：DZY 編號、姓名、單位、在職；LINE 綁定仍來自打卡名冊（透過對照找到同一人）。
- 拿掉「打卡同步」按鈕與跨店主店判定表（主店直接看管理系統）。
- 同仁 LINE 自動登入照舊，感受不到變化。

### F7 一致性檢查（首頁待辦）
- 每天比一次：管理系統在職人數 vs 各店打卡名冊在職人數；有人在打卡上卻沒對照、或對照到的打卡編號已停用 → 首頁「待辦與異常」列出來。

## 5. 不能出的錯（驗收時逐條測）
1. 對照錯人：任何對照沒有人工確認不生效；同名一律人工。
2. 新人建好但打不了卡：管理系統成功、打卡失敗時一定看得到、能重試。
3. 離職漏停：停用後任何一店打卡名冊仍是在職 = 失敗。
4. 真名進 repo：dzy repo 是 public，名冊與比對檔只放 gitignore 的 spike/ 或 Mac mini。
5. 打卡既有流程（打卡、LINE 綁定、核定、薪資讀名冊）一行不改；打卡端只「純新增」給管理系統呼叫的端點。

## 6. 成功的樣子
- 新人：店長在管理系統建檔 → 同一天打得了卡、綁得了 LINE、佈告欄看得到。
- 離職：按一次 → 隔天起（或依第 2 題）全部系統停用。
- 對照表上線後，一致性檢查連續 7 天零異常。
