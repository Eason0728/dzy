# 需求：排班管理｜總部自填排班＋央廚固定排班（2026-10-24 草稿，待 Eason 確認）

> 前提：門市自動排班正在搬進管理系統「人資部門 → 排班管理」（營運系統 `docs/autoschedule/hr-move-spec.md`，分支 schedule-hr，未上線）。本案在**同一個「排班管理」**裡再加兩種排班方式。**本案等搬家上線、穩定後才開工。**

## 0. 要 Eason 先釐清的 3 題（答完才寫規格）
1. **品牌辦公室的人（區督導、總監、行政同仁）算不算「總部同仁」？** 推薦：算（他們掛在鼎兆元總部底下），一樣自己填班。
2. **央廚廠長要能改央廚的例外**（加班、換班）——廠長要開放排班管理嗎？推薦：開放廠長（央廚其他同仁不開放，照你的答覆）。
3. **總部班別誰設定？** 推薦：人資在排班管理設一份「總部班別」（例如 09:00–18:00、10:00–19:00），全總部共用；同仁每天從清單選。

## 1. 要解決的問題
- 門市排班是店長排全店；總部的人上班時間各自不同，由主管一個個排不實際 → 讓**總部同仁自己填**，主管核准。
- 央廚上班規則固定（平日上班，六日、國定假日、補假休）→ **不用人排**，系統自動產生，廠長只改例外。
- 三種班表都要跟門市一樣：送到同仁的 LINE 出勤班表、在考勤管理核定工時時比對打卡（晚到早退提醒）。

## 2. 三種排班方式（都在管理系統「排班管理」，頁頂三個分頁）
| | 門市排班（搬家中，已做） | 總部排班（新） | 央廚排班（新） |
|---|---|---|---|
| 誰的班 | 各門市同仁 | 鼎兆元總部同仁 | 央廚同仁 |
| 怎麼排 | 店長排全店＋自動排班 | **每人每天自己選班**（從總部班別清單） | **系統自動**：平日上班、六日＋國定假日＋補假休；上哪個班由廠長設定 |
| 期間 | 四週一期（T01…） | **一個月** | 一個月 |
| 誰核准 | 店長鎖定 | **直屬主管核准**（照管理系統「往上一層」：部門同仁→部門總監；總監→執行長以上） | 廠長改完例外就生效 |
| 截止 | — | **每月 20 號開放填下個月、25 號前送出**；25 號還沒送出，首頁提醒本人與主管；沒填就是沒班表，不代填 | 每月自動產生下個月 |
| 核准後要改 | 解除鎖定再改 | **改了哪幾天就送哪幾天再核准**；核准前 LINE 與打卡比對照舊版 | 廠長直接改 |
| 送 LINE 出勤班表 | 是 | 是（核准後） | 是 |
| 考勤管理比對打卡 | 是 | 是 | 是 |

## 3. 誰看得到「排班管理」選單
- **只有總部同仁跟店長**（Eason 2026-10-24）。央廚同仁不開放（廠長待第 0 節第 2 題）。門市一般同仁照舊沒有。
- 三個分頁大家都看得到分頁名；沒權限的分頁點進去顯示「沒有權限」。
- ⚠ 這會改掉搬家案「看得到的人＝考勤管理那批」的決定：區督導、總監、人資主管、管理員要不要保留？推薦：人資主管、管理員保留（要看全部）；區督導、總監依第 0 節第 1 題算總部同仁、只看得到總部分頁裡自己的班，門市分頁不給（他們本來就只能看）。**這條會回頭改搬家案，要你確認。**

## 4. 總部排班的使用者故事
- 同仁：20 號起打開「排班管理 → 總部排班」，看到下個月月曆；每天選班或「休」；系統當場提醒違規（7 天內沒有例假、班與班間隔不到 12 小時…）；按「送出」→ 等主管核准。
- 主管：首頁提醒「N 位同仁的 11 月班表等你核准」；打開看到部屬的月曆，可以一次核准或退回（退回要寫原因）。
- 核准後：班表送到同仁的 LINE 出勤班表；考勤管理核定工時時，每人顯示「班表」那行。
- 人資：看得到全總部的班表與誰還沒填、誰還沒核准；可以設總部班別。

## 5. 央廚排班的使用者故事
- 每月（例如 20 號）系統自動產生下個月：每位央廚同仁平日上「他的固定班」，六日、國定假日、補假是休。
- 廠長：打開「排班管理 → 央廚排班」改例外（某天加班、某人換班、請假），存了就生效、送 LINE。
- 國定假日與補假用門市排班同一份假日表（目前到 2027-12-31）。

## 6. 探到的事實（2026-10-24）
- LINE 出勤班表：營運系統鎖定時把整期班表送到光復那套打卡 Apps Script（`SchedPub.gs`），接收端**沒有店別白名單**，依同仁編號存；11/1 起 LINE 出勤班表依日期讀這份。總部 `hq`、央廚 `cf` 在營運系統出勤核定都有打卡店別（`server/proxy/duty.js:21-36`）。**總部、央廚同仁的 LINE 出勤班表能不能照門市方式顯示：未確認**（要查 LINE Hub 的店別設定，規格階段實測）。
- 考勤比對：營運系統 `dayPlan` 依店讀 `sch_days`（`server/schedule.js:747-768`），考勤核定頁自動顯示「班表」那行（`web/modules/duty/approve.js:98-112`）。資料放一起（Eason 選）＝總部、央廚只要當成兩個「店」，比對就自動有。
- 直屬主管：管理系統 `Staff.gs stfReviewNeed_` 已有「往上一層」規則（總部：部門同仁→同部門總監；總監、管理部→執行長以上）。
- 國定假日：`holidays.json` 到 2027-12-31，補假也列在內（名稱「補假」）。
- 既有系統：沒有總部排班系統；`~/mala-schedule`（月曆版，只有光復，2027-01-01 停用）不適用。

## 7. 不做／之後再說
- 總部同仁自己「看別人的班」、換班互助。
- 加班自動申請（超時只提醒，加班照現有考勤申請流程）。
- 央廚同仁自己看系統裡的班表（看 LINE）。

## 8. 風險
- 總部人數多、主管核准是新流程：25 號截止若常沒填，LINE 出勤班表會空，考勤比對沒有依據。→ 首頁提醒＋人資看得到未填名單。
- 這案會動到搬家案剛定的「誰看得到排班管理」（第 3 節）。
