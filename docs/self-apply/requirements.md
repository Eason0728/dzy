# 新進同仁自行申請帳號（主管通過才給編號）需求

狀態：Eason 2026-11-06 選定 **1A 2A 3A 4B 5B**。確認頁 https://claude.ai/artifact/RzCQJZkuiSmrKE4V89wDzD

## 0. 背景

現行流程（Staff.gs `handleClaimLookup_`／`handleClaimSubmit_`）：同仁一定要先被人資匯入或店長「新增同仁」建檔、拿到 DZY 編號，
才能在登入頁「第一次使用」認領；名冊查無 → 「名單上找不到這個名字，請找後台」。

Eason 2026-11-06：新進同仁第一次申請時，若名冊沒有，可以自己送申請；**主管按通過後才自動建立最新 DZY 編號**。
**不做門市邀請碼**（Eason 明確決定）。

這推翻 2026-08-17「不做自助註冊」：網址公開，外人可以送申請，但沒有主管通過就開不了帳號。

## 1. 範圍

- 登入頁「第一次使用」查無名字時，多一個入口「我是新進同仁，申請帳號」。
- 申請單填：姓名、手機、生日、居住地址、密碼（兩次）、單位、職稱（欄位與驗證沿用認領 `stfClaimWrite_`）。
- 申請送出不產生編號、不寫 staff／users，另存申請分頁（暫名 `staff_apply`），密碼只存 salt＋hash。
- 審核者在「我的資料 → 待審核」看到申請；通過當下：
  1. 編號＝`stfMaxEmpNum_() + 1`（與「新增同仁」同一套，含停用、離職，不回收）；
  2. 寫 users 列（帶申請時的 salt／hash）＋ staff 列（status active）；
  3. 單位有門市打卡店 → 開打卡 add 單（同 `handleStaffCreateByUnit_`）；
  4. staff_log 記 `apply_approve`（不寫個資）。
- 退回：必填原因，申請單作廢，不產生編號。
- 現有「新增同仁」「匯入」「認領」照舊並存。

## 2. 防呆（不做邀請碼的替代）

- 限流沿用 `stfGlobalFlood_`，新開一桶 `apply`（600／10 分鐘），格式錯不計。
- 同名處理：
  - 名冊有同名「未認領」→ 不收申請，導回認領（避免一人兩號）；
  - 同單位已有同名非停用同仁 → 擋（同 `clkNameClash_`）；
  - 同一支手機已有待審申請 → 擋。
- 申請只出現在所選單位的審核者清單，不會全集團都收到。

## 3. Eason 的決定（2026-11-06：1A 2A 3A 4B 5B）

| 題 | 問題 | 決定 |
|---|---|---|
| Q1 | 新人怎麼知道自己的編號（登入只認 DZY 編號，不認手機） | A：通過畫面給審核者看編號＋新人在登入頁輸入姓名＋手機可查進度與編號 |
| Q2 | 誰能按通過 | A：跟「新增同仁」一樣（店長、廠長、兼任店長、有「可新增同仁」的正職、人資；職稱不可高於自己） |
| Q3 | 審核時能不能改資料 | A：可改職稱、必填到職日（新增同仁本來就要到職日）；單位填錯就退回 |
| Q4 | 沒人處理的申請 | **B**：不過期，一直留到有人處理（核准或退回） |
| Q5 | 申請時能選哪些單位 | **B**：全部單位開放（品牌辦公室由總監、總部部門由部門總監審） |

## 4. 不做

- 門市邀請碼（Eason 2026-11-06 決定不做）。
- 用手機號碼登入。
- 申請時上傳證件或照片。
